# Stock Management System (裁量トレード支援ツール)

## 概要

本システムは、日本株のスイングトレードを対象とした**裁量トレード支援システム**です。
「自動で売買を行って利益を出すBot」ではなく、トレーダーが自身のルールに基づき、適切なタイミングで判断を下すための「監視・分析・記録」を自動化することを目的としています。

## コンセプト

* **自動売買ではなく「支援」**: 最終的な売買判断は人間が行います。システムは判断に必要な情報を整理し、ルール逸脱を監視します。
* **実運用前提の設計**: 勉強用のサンプルコードではなく、実際にcronでの常時監視、ルールの外部化、ログ記録を行うことを前提に設計されています。
* **スイングトレード特化**: デイトレードのような高頻度取引ではなく、中期的なトレンドフォローを想定しています。

## 主な機能

1. **市場監視 & 分析**
    * 定期的な株価データの取得とテクニカル指標（MACD, Bollinger Bands等）の計算。
    * 設定されたトレードルールに基づくシグナル検知。

2. **Web UI (Dashboard & Settings)**
    * **Dashboard**: 分析結果やチャート画像をブラウザ上で閲覧可能。
    * **Settings**: プログラムを停止することなく、JSONベースでトレードルール（損切りライン、利確ラインなど）を調整可能。

3. **ルール管理 & 記録**
    * トレードルールの変更履歴を保存し、「なぜルールを変えたか」を記録・追跡可能。
    * 定量的な基準（Profit Factor, Drawdown等）に基づくルール見直しアラート。

## トレード戦略仕様

本システムが対象とするスイングトレード戦略を整理します。実際の数値（RSI閾値・ATR倍率・スコア配点など）はすべて `python/trading/rules/` 配下の3ファイルに集約されており、運用中に調整できます。

| 論理グループ | 定数ファイル | 扱う内容 |
|------------|------------|---------|
| `swing_trade_rules` | `python/trading/rules/swing_trade_rules.py` | チャートパターン条件（W底、逆三尊、フラッグ、トライアングル等） |
| `indicator_settings` | `python/trading/rules/indicator_settings.py` | RSI・MACD・ATR・EMA・ボリンジャー・出来高の数値 |
| `risk_management` | `python/trading/rules/risk_management.py` | 損切り・利確・リスクリワード・スコアリング設定 |

### 前提（時間軸の固定）

- メイン: **日足**
- 補助: 4時間足（エントリー精度用）
- 保有期間: **3〜10営業日想定（最大2週間）**

### 共通フィルター（全パターンの前提条件）

1. **トレンド環境**
    - 買い: 20EMA ≥ 50EMA
    - 売り: 20EMA ≤ 50EMA
2. **ボラティリティ**: Average True Range が過去20日平均以上
3. **出来高**: ブレイク時に直近5日平均の1.2倍以上

### 購入フラグ（ロング条件）

| パターン | 主条件 | 補強指標 |
|---------|-------|---------|
| ダブルボトム（W底） | 5〜12営業日で2点形成・価格差±3%以内・ネックライン上抜け | RSIが50→60へ上昇中 |
| 逆三尊 | 7〜15営業日・右肩が左肩より高い・ネックライン上抜け | MACDゴールデンクロス |
| 上昇フラッグ | 強い上昇（+5〜10%）後の3〜7日調整・平行チャネル上抜け | 出来高: 調整中に減少→ブレイクで増加 |
| 上昇トライアングル | 5〜15日・上値水平＋安値切り上げ・レジスタンス突破 | RSI 55以上維持 |
| 切り下げ→レジサポ転換 | 下降トレンドライン突破後、サポートとして機能 | リテスト成功時にエントリー |

### 売却フラグ（ショート/利確条件）

| パターン | 主条件 | 補強指標 |
|---------|-------|---------|
| ダブルトップ | 高値2点（±3%以内）・ネックライン割れ | RSI 70→低下 |
| 三尊（ヘッドアンドショルダー） | 右肩が弱い・ネックライン割れ | MACDデッドクロス |
| 下降フラッグ | 下落後の小反発（3〜7日）・下抜け | — |
| 下降トライアングル | 下値水平＋高値切り下げ・下抜け | — |
| 切り上げ→レジサポ転換 | 上昇トレンドライン割れ・戻り売り成功 | — |

### 購入推奨タイミング（ロング）

**基本原則: 「予測で入らず、確認で入る」**

エントリーは以下の2パターン:

| タイミング | 説明 | 適性 |
|-----------|------|------|
| ブレイク当日終値 | ネックライン/レジスタンスを終値で上抜け＋出来高増 | シンプル・再現性高い |
| リテスト押し目 | ブレイク後1〜3日以内の軽い戻りで反発確認 | 勝率重視 |

パターン別の具体タイミング:

| パターン | 推奨タイミング |
|---------|-------------|
| ダブルボトム / 逆三尊 | ネックライン上抜け or 押し目 |
| 上昇フラッグ | チャネル上抜け直後（初動が命） |
| 上昇トライアングル | 水平線ブレイク＋出来高増 |
| レジサポ転換 | リテスト成功がほぼ必須 |

### 売却推奨タイミング（ショート/利確）

**基本原則: 「期待で持たず、崩れで出る」**

#### ショートエントリー

| タイミング | 説明 |
|-----------|------|
| ブレイク確定 | ネックライン/サポートを終値で下抜け |
| 戻り売り | 下抜け後1〜3日の戻りでレジスタンス化を確認 |

#### ロング利確の3パターン

| 種別 | 条件 |
|-----|------|
| 目標到達（機械的） | RR 1.5〜2倍到達 or 直近高値 |
| 弱さ検知（テクニカル） | RSI 70→低下 / 上ヒゲ連発 / 出来高減少+上昇 |
| 売りパターン出現（最強） | ダブルトップ / 三尊 / 下降トライアングル → 即撤退 |

#### 時間軸ベースの出口ルール

| 経過日数 | アクション |
|---------|----------|
| 5営業日で伸びない | 一部 or 全撤退 |
| 10営業日で横ばい | 全撤退 |
| 2週間経過 | 強制クローズ検討 |

### 損切り・利確ルール

- **損切り**: 直近安値（ロング）/高値（ショート）または ATR × 1.2
- **利確**: リスクリワード比 **1:1.5 以上**。もしくは前回高値/安値、フィボナッチ（1.272 / 1.618）

### スコアリング（実戦向け・7点満点）

| 加点項目 | 配点 |
|---------|-----|
| パターン成立 | +2 |
| 出来高条件 | +1 |
| RSI 一致 | +1 |
| MACD 一致 | +1 |
| トレンド一致 | +2 |

- **合計 5点以上でエントリー**（`SCORE_THRESHOLD_ENTRY`）
- 4点はウォッチ段階として UI 表示対象（`SCORE_THRESHOLD_WATCH`）

### よくある罠

- フラッグが「ただのレンジ」に終わる
- トライアングル未完成で先走りエントリー
- 出来高の無視
- 地合い無視（指数下げ中のロング）

## アーキテクチャ

```mermaid
graph TD
    User[User] -->|Browser| WebUI[Web UI (Cloud Run)]
    WebUI -->|Read/Write| Rules[Rules JSON (GCS)]
    WebUI -->|Read| Charts[Charts (GCS)]
    
    Cron[Cron Job (GCE)] -->|Read| Rules

    Cron -->|Analyze| Logic[Analysis Logic]
    Logic -->|Save| DB[(PostgreSQL)]
    Logic -->|Generate| Charts
```

* **Backend**: Python, FastAPI
* **Frontend**: HTML, Vue.js (Web UI)
* **Database**: PostgreSQL (SQLAlchemy + Alembic)
* **Infrastructure**: Google Cloud Platform (Cloud Run, GCE, GCS)

## セットアップ手順 (開発環境)

### 前提条件

* Python 3.12+
* Docker & Docker Compose (DB用)

### インストール

1. リポジトリのクローン

    ```bash
    git clone https://github.com/your-account/stockManagement.git
    cd stockManagement
    ```

2. 依存ライブラリのインストール

    ```bash
    python -m venv .venv
    source .venv/bin/activate
    pip install -r requirements.txt
    ```

3. データベースの起動

    ```bash
    docker-compose up -d db
    ```

4. Web UIの起動

    ```bash
    uvicorn python.web.app:app --reload --port 8888
    ```

    ブラウザで `http://localhost:8888` にアクセスしてください。
