# ユーザーレビューに基づくUI・DB連動の改善要件 (2026-02-22)

## 1. 目的
ユーザーからのレビューフィードバックに基づき、以下の3点を改善・実装する。
1. シグナル分析（Check Signals）のトリガーUIを既存の紫ボタンに統合し、安全に動作させる。
2. 売却（Sell）および削除（Delete）時の完了通知（トースト表示）が短すぎて目視できない問題を解決する。
3. ローカル開発環境において `data/my_stock_local.csv` とのデータ連動を徹底させる。

## 2. 機能要件

### 要件A: CheckSignalボタンの機能統合
- **対象**: `index.html` ヘッダータブ横の「Check Signals」ボタン（紫色: `bg-purple-600`）。
- **内容**:
  - 現在の実装でボタン自体の関数 (`analyzeSignals`) は存在しているが、バックエンド (`/api/signals/analyze`) 呼び出し時に `signals` テーブルが存在しないなどのエラーがログに見られた。
  - バックエンドのアナライズAPI内で、対象テーブルの安全な初期化（`init_db()`など）が行われること。
  - あるいは、既存の分散しているシグナル関連の機能をこのボタン（とそこから呼ばれる処理）に集約し、確実に動作するようにする。

### 要件B: Sell/Deleteアクションのトースト表示改善
- **対象**: `index.html` 内の `sellStock()` および `deleteStock()` メソッド、UI表示。
- **内容**:
  - `sellStock()` 完了時は現状 `alert()` （ブラウザの警告ダイアログ）が使われているが、これを `deleteStock()` と同様の非同期なトースト通知（`this.toastMessage` による表示）に変更する。
  - 現在、トースト表示時間が7000msに設定されていても、「表示が消えるのが早過ぎて確認できない」という指摘がある。
  これは、トースト表示直後に実行される `this.fetchCharts()` によるページ全体の再レンダリングや、データ再読み込みの影響でUIコンポーネントがリセットされている可能性が高い。
  - 改善策として、アクション完了後のデータリロード（`fetchCharts`）時にトーストメッセージ変数をクリアしないようにする、あるいはVueのライフサイクルを調整して通知が最低でも3〜5秒間は画面に安定して描画され続けるように実装を修正する。

### 要件C: `my_stock_local.csv` 連動の徹底
- **対象**: DB同期機能 (`database.py`) および設定ファイル (`config.py`)
- **内容**:
  - 「`data/my_stock_local.csv` と連動していない」という指摘に基づき、アプリケーション起動時にトリガーされるCSVからDBへの同期機能（`sync_csv_to_portfolio`）が、確実に**現在の環境に応じたCSVファイル**（ローカル起動なら `data/my_stock_local.csv`）を対象とするように見直す。
  - 修正: `app.py` などの起動時処理や `buy_and_sell_stock.py` の更新処理時に `my_stock.csv` というパス文字のハードコーディングが残っていないか検証し、すべて `config.codes_path` に一元化されていることを保証する。
