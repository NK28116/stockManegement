## 2. 機能要件

### 2-1. トレード戦略の実装（週足スイングトレード）
- **環境認識フィルター（必須）**: 40週移動平均線（40MA）を用いたトレンド判定。
  - ロング条件: 終値 > 40MA かつ 40MAが上向き
  - ショート条件: 終値 < 40MA かつ 40MAが下向き
- **買いパターン検出（週足）**:
  - ダブルボトム、逆三尊、上昇フラッグ、上昇トライアングル、切り下げラインブレイク。
  - 出来高増加の確認（20週平均との比較等）。
- **売りパターン**: 買いの完全対称。ただしショートは慎重に行うロジックとする。
- **リスク管理（最重要）**:
  - 損切り: エントリー時ATR(14) × 1.5 または直近スイング安値割れ。
  - 利確: 最低RR = 1:2、推奨 = 1:3。
  - ポジションサイズ: 1トレードの最大損失 = 資金の1%。
- **保有ルール**:
  - 8〜12週間進展なしで手仕舞い。
  - トレーリングストップ: 20週MA割れで利益確定。
- **パターンスコアリング**:
  - 長期トレンド一致(+3)、パターン完成(+3)、出来高増加(+2)、RSI確認(+1)、RR>2(+1)
  - 合計8点以上でエントリー対象とする。
- **強化ポイント**: マルチタイムフレーム確認（週足で方向、日足でタイミング）、地合いフィルター（日経/S&P > 40週MA、VIX低下）、セクター強度。

### 2-2. 分析ロジックの結合と実装 (`python/watch/analyze.py`)
- `main()` 関数から、登録されている全保有・監視銘柄に対して上記のトレード戦略アーキテクチャ（環境認識→パターン検出→スコアリング→リスク計算→通知）を実行するよう改修する。

### 2-3. シグナル履歴の永続化 (データベース)
- 判定されたシグナルの結果（銘柄、発生日時、シグナル種別、スコア、根拠パターンなど）をデータベースに保存する。
- 過去のシグナル履歴を検索・フィルタリングできる仕組みを整える。

### 2-4. フロントエンド連携とUI表示
- バックグラウンドでの分析完了後、フロントエンドで最新のシグナル情報を取得できるようにする。
- `index.html` の画面上で、銘柄ごとのスコアや検出パターンを確認できるようにUIを修正する。

## 3. 非機能要件
- ボタンの応答時間は2秒以内とする（重い分析処理自体はバックグラウンドで行う）。
- シグナル生成のロジックはモジュール化し、将来的なルール変更に対応しやすくする。

## 4. 制限事項・システム要件
- クラウドサーバー（Cloud Run 等）を使用する場合は、必ず Always Free の枠内で収まるようリソースを最適化する。
- 特に重いバッチ処理やDB保存を伴う場合、ローカル環境（Intel MacBook Pro + Ubuntu）での実行が可能であればそちらを優先・活用する構成を検討する。
