STOCKMANAGEMENT · しくみの解説

株の「健康診断」アプリのしくみ

このアプリは、自分が持っている株や気になる株を記録しておくと、毎日の値動きから「買いどき・売りどきの候補」を計算して画面に並べてくれる道具です。このページでは、その中で使っている数学とプログラムの技術を、高校の数学Ⅰ・Bの知識で読めるように説明します。

1. 何をするアプリ？ 2. データの流れ 3. 平均とばらつき 4. 新しい値を重く見る平均 5. 勢いを測る RSI 6. 形を見つける 7. 7 点満点の採点 8. 損切りと利確の決め方 9. Web アプリの技術 10. 安全のしくみ
CHAPTER 1

何をするアプリ？

株の値段は毎日上がったり下がったりします。人間がすべての銘柄のグラフを毎日見比べるのは大変なので、このアプリは次の 3 つを自動でやってくれます。

やること画面のどこで見える？
記録する — 持っている株の数・買った値段・目的（長期、優待目的など）を保存するDashboard タブの一覧と購入フォーム
グラフにする — 値動きと、後で説明する指標（移動平均や MACD）を画像にする一覧の Plots / ChartImg の列
採点する — 「今は買いの形になっているか」を 7 点満点で点数化し、損切り・利確の目安の値段を計算するSignals タブ

ここで計算される数字は「過去の値動きから見るとこういう形をしている」という目安です。未来の値段を当てるものではありません。最終的に売り買いを決めるのは人間です。

CHAPTER 2

データの流れ

毎日決まった時間に、クラウド上のサーバーが自動でプログラムを動かします（scripts/cron_daily.sh）。流れは次の順番です。

株価を取ってくるYahoo! Finance から始値・高値・安値・終値・出来高をもらう（yfinance）
計算するPython の表計算ライブラリ pandas で平均や RSI を計算
グラフを描くmatplotlib で画像を作る。日本語が文字化けしないフォント設定つき
保存する画像と保有株の表を Google Cloud Storage へ。採点結果はデータベースへ
見せるWeb アプリ（FastAPI）が読み出し、ブラウザ（Vue）が画面に並べる

株価のデータは 1 日 1 本の「日足」と、1 週間 1 本の「週足」の 2 種類を使います。日足は 1 本につき 4 つの値段（始値・高値・安値・終値）を持っているので、「ろうそく足」という形で描くことができます。採点（7 章）は週足で行います。数日〜2 週間で売り買いする「スイングトレード」という作戦を想定しているからです。

CHAPTER 3 · 数学Ⅰ「データの分析」

平均とばらつき — 移動平均とボリンジャーバンド

移動平均（いどうへいきん）

毎日の終値はギザギザしていて、流れが見えにくいです。そこで「直近 N 日の平均」を毎日計算し直して線でつなぎます。これを移動平均といいます。計算する範囲が 1 日ずつ横に「移動」していくので、この名前がついています。

MAt = 1N( Pt + Pt−1 + … + Pt−N+1 ) Pt は t 日目の終値。アプリでは N = 20 を使います（BOLLINGER_PERIOD = 20）。

標準偏差とボリンジャーバンド

平均だけでは「どのくらい暴れているか」が分かりません。そこで数学Ⅰで習う標準偏差 σ（シグマ）を、同じ直近 N 日について計算します。

σt = √( 1N − 1 Σ ( Pi − MAt )2 ) pandas の標準では N ではなく N − 1 で割ります（標本標準偏差）。教科書の N で割る式とほとんど同じ値になります。
上のバンド = MAt + 2σt　　下のバンド = MAt − 2σt データが正規分布（つりがね型）に近ければ、約 95% の値がこの帯の中に収まります。帯の外に飛び出したら「いつもより大きく動いた」という合図です。

さわってみよう

終値（架空のデータ） 移動平均 MA MA ± kσ の帯 帯の外に出た日

N を大きくすると線がなめらかになり、そのぶん動きへの反応が遅くなります。k を大きくすると帯が広がり、帯の外に出る日が減ります。k = 2 でも帯の外に出る日が 5% より多くなることがありますが、これは値動きに「流れ」があって、つりがね型の分布どおりにはならないためです。本物の株価でも同じことが起きます。

CHAPTER 4 · 数学B「数列」

新しい値を重く見る平均 — EMA と MACD

ふつうの移動平均は、20 日前の値も昨日の値も同じ重さで扱います。でも、相場では「最近の動き」の方が大事なことが多いです。そこで、新しい値ほど重みを大きくする指数移動平均（EMA）を使います。

EMAt = α · Pt + (1 − α) · EMAt−1　　α = 2N + 1 今日の値に α、昨日までの EMA に 1 − α をかけて足します。N = 12 なら α ≈ 0.154 です。

この式を何回もくり返し代入すると、k 日前の値にかかる重みは α(1 − α)k になります。これは公比 1 − α の等比数列です。古い値ほど重みが一定の割合で小さくなっていき、重みをすべて足すと等比数列の和の公式から 1 に近づきます。「指数」移動平均という名前はここから来ています。

MACD = EMA12 − EMA26　　シグナル = MACD の EMA9 短い EMA（12）が長い EMA（26）より上にあれば、最近の値段が強いということです。MACD がシグナル線を下から上に追い越すことを「ゴールデンクロス」と呼び、上昇の始まりの目安にします（python/utils/indicators.py）。
CHAPTER 5 · 比と割合

勢いを測る RSI

RSI（相対力指数）は、「最近の値動きのうち、上がった分がどのくらいの割合か」を 0〜100 の数で表したものです。直近 14 日について、前の日より上がった日の上がり幅の平均と、下がった日の下がり幅の平均を求めます。

RS = 上がり幅の平均下がり幅の平均　　RSI = 100 − 1001 + RS = 100 × 上がり幅の平均上がり幅の平均 + 下がり幅の平均 2 つ目の形に変形すると、「全体の動きのうち上がった分の割合 × 100」だと分かります。ずっと上がり続ければ 100、ずっと下がり続ければ 0 に近づきます。
RSI の値読み方アプリでの使い方
70 以上買われすぎ（上がりすぎ）持っている株の「弱り始め」の目安
40〜65ほどよく上向き買いの採点で +1 点（RSI_LONG_RANGE）
30 以下売られすぎ（下がりすぎ）参考値
CHAPTER 6 · 関数とグラフ

チャートの「形」を見つける

ベテランの投資家は、グラフの形（チャートパターン）を見て判断します。アプリはその見方を、数学の言葉に置き換えて判定しています（python/watch/analyze.py）。

大きな流れ（トレンド）— 40 週移動平均とその傾き

約 10 か月分にあたる 40 週の移動平均を作り、次の 2 つの条件を両方満たせば「上昇トレンド（LONG）」と判定します。下降トレンド（SHORT）はその逆です。

終値 > MA40　かつ　MA40今週 − MA40先週 > 0 2 つ目は、関数の増減を調べるときの「変化量が正なら増加」と同じ考え方です。

谷を見つける — 極小値と W 底

安値の列 L1, L2, … の中で、両隣より小さい点を「谷（極小値）」とします。最近の谷 2 つの高さの差が 5% 未満なら、W の字に見えるダブルボトム（2 回底を打って上がる形）とします。谷が 3 つあって真ん中が一番深く、両端が同じくらいの高さなら逆三尊です。

Li−1 > Li < Li+1 なら谷　　| p1 − p2 |p1 < 0.05 なら W 底

傾きを測る — 最小二乗法

直近 15 週の高値と安値に、それぞれ一番よく当てはまる直線を引きます。高値の線が下向きで、安値の線が上向きなら、値動きが三角形にすぼまっていくトライアングルの形です。「一番よく当てはまる直線」の傾き a は、数学Ⅰの相関で習う式と同じもので求めます。

a = Σ ( xi − x̄ )( yi − ȳ )Σ ( xi − x̄ )2 分子は共分散の形、分母は分散の形です。x は週の番号（0, 1, 2, …）、y はその週の高値または安値です。

出来高（売買された株の数）

今週の出来高が、直近 20 週の出来高の平均より多ければ「注目が集まっている」とみなします。形がそろっても、売り買いする人が少なければ信用しにくいからです。

CHAPTER 7

7 点満点の採点

ここまでの判定を組み合わせて点数をつけます。1 つの指標だけで決めると外れやすいので、複数の条件が同時にそろったときだけ「エントリー候補」にする作戦です（python/trading/rules/risk_management.py）。下のチェックを付けたり外したりして試してみてください。

5 / 7 点 —

5 点以上でエントリー候補、4 点で様子見（監視）です。この基準の数字は設定ファイルにまとめてあり、Settings タブから変更案を作って、Simulation タブで過去のデータに当てはめて試せます（バックテスト）。

CHAPTER 8 · 確率と期待値

損切りと利確の決め方 — ATR と期待値

買う前に「いくらまで下がったらあきらめるか（損切り）」と「いくらまで上がったら売るか（利確）」を決めておくのが、このアプリの考え方です。その幅は、その株がふだんどのくらい動くかに合わせて決めます。ふだんの動きの大きさを表すのが ATR（平均的な値幅）です。

真の値幅 TR = max{ 高値 − 安値, | 高値 − 前の終値 |, | 安値 − 前の終値 | }　　ATR = TR の 14 期間の平均 前の日から窓をあけて（すき間をあけて）動いた分も含めるため、3 つのうち最大のものをとります。
損切り = 買値 − 1.2 × ATR　　利確 = 買値 + 1.8 × ATR 失うかもしれない幅 1.2 ATR に対して、得られるかもしれない幅は 1.8 ATR です。比は 1.8 ÷ 1.2 = 1.5 になり、これを「リスクリワード比 1.5」と呼びます。

ここで期待値を考えます。勝つ（利確に届く）確率を p、負ける（損切りに届く）確率を 1 − p とすると、1 回あたりの平均の損益は次のようになります。

E = 1.8p − 1.2(1 − p) = 3.0p − 1.2　（単位は ATR） E > 0 になるのは p > 0.4 のとき。つまり勝率が 40% を超えれば、負けの方が多くても平均ではプラスになる設計です。

計算してみよう

項目計算値
損切り買値 − 1.2 × ATR
利確買値 + 1.8 × ATR
1 株あたりの期待値1.8 × ATR × p − 1.2 × ATR × (1 − p)

もう一つ、時間のルールもあります。5 日たっても動かなければ見直し、10 日横ばいが続いたら撤退を考え、14 日を超えて持ち続けるなら手じまいを検討します（TIME_STOP）。予想どおりに動かない株にお金を置いたままにしないためです。

CHAPTER 9

Web アプリの技術

役割使っている技術たとえると
サーバー（裏方）Python + FastAPI注文を受けて料理を出す厨房。/api/charts/list のような住所（URL）ごとに担当の関数がある
画面（表側）Vue.js + Tailwind CSSお店のホール。サーバーから受け取ったデータ（JSON）を表やボタンに組み立てる
データベースPostgreSQL（本番）/ SQLite（手元の開発用）台帳。保有株、採点結果、ウォッチリストを表の形で保存する
ファイル置き場Google Cloud Storage倉庫。グラフ画像と保有株の CSV を置く
サーバーを動かす場所Google Cloud（Cloud Run / GCE）、Docker貸し店舗。使った分だけ料金がかかり、しばらく使わないと眠る
見守りCloud Logging / Monitoring と System Monitor 画面防犯カメラと日報。エラーや CPU の使い方をまとめて表示する
AI との連携MCP サーバーAI アシスタントがウォッチリストやメモを読み書きするための窓口

サーバーがしばらく使われないと眠る仕組みなので、最初に開いたときは起きるまで少し待ちます。そのため、起動の準備（データベースの準備など）は画面の表示と同時に裏で進め、待っている間は「起動中」と表示するようにしています。30 秒たっても応答がなければ「再試行」ボタンを出します。

ブラウザが 1 つの画面を表示するまでの流れは「HTML をもらう → CSS と JavaScript をもらう → JavaScript が API にデータを頼む → 届いたら表を作る」の順です。画面の一覧の並び順（保有中 → 次回購入 → 売却予定 → 監視中 → 除外）も、サーバーが持っている定義をもとに JavaScript が並べ替えています。

CHAPTER 10 · 関数と整数

安全のしくみ — パスワードは保存しない

このアプリは管理者だけが使うので、パスワードでログインします。ただし、パスワードそのものはどこにも保存しません。代わりに保存するのは、パスワードを「ハッシュ関数」に通した結果です。

保存する値 = H( パスワード, ソルト ) を 390,000 回くり返したもの H は SHA-256 というハッシュ関数です（PBKDF2 という方式）。入力が 1 文字違うだけで出力がまったく別物になり、出力から入力を逆算することは事実上できません。ソルトはランダムな文字列で、同じパスワードでも保存する値が変わるようにするためのものです。

ログインのときは、入力されたパスワードを同じように計算し、保存してある値と一致するかを比べます。39 万回もくり返すのは、わざと計算を重くするためです。正しい人が 1 回試すだけなら一瞬ですが、パスワードを総当たりで当てようとする攻撃者には、何億回もの重い計算を強いることになります。

しくみ何を防ぐか
ログイン状態を、署名つきの Cookie（HMAC）で覚える。有効期限は 12 時間Cookie の中身を書き換えてなりすますこと。秘密の鍵がないと正しい署名が作れない
5 回まちがえたら 15 分ロックパスワードの総当たり
公開してよい道（ログイン画面など 5 つ）以外は、すべてログイン必須新しい画面を追加したときに、保護をかけ忘れること
画面に出すログの token=… や password=… を *** に置き換えるSystem Monitor の画面から秘密の値が漏れること
本番でパスワードの設定がなければ、アプリが起動しない設定し忘れたまま、誰でも入れる状態で公開されること

「失敗したら安全な側に倒れる」設計をフェイルクローズといいます。たとえば鍵が壊れたら、ドアが開きっぱなしになるのではなく、閉まったままになるようにしておく考え方です。
