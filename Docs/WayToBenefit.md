# 収益化・提供価値に関する考察

> 本ドキュメントは、当初「株式分析ツールの公開価値」を論じたものだったが、
> issue #21 の議論を経て **「ルールベース監視・改善プラットフォーム」** という再定義に更新した。
> 基本方針は一言で言えば —— **「株は入口、ルール運用支援が本命」**。

---

## 0. 結論（先に方針）

このプロダクトは、表面的には日本株スイングトレードの裁量支援ツールである。
しかし構造を抽象化すると、**「対象を観測し、ルールを適用し、変化を検知し、行動を記録し、ルールを改善する」** という汎用的な監視・改善サイクルそのものである。

したがって収益化の基本方針は以下の通り。

1. **株式投資という具体的ユースケースで無料公開**し、集客とプロダクト価値の証明（Social Proof）を行う。
2. **ルール運用・行動管理・改善支援の機能を有料化**する。課金対象は「分析できること」ではなく「決めたルールを継続して守れること」。
3. 利用実績をもとに、株式以外のドメイン（生物観察・学習管理・在庫・健康管理など）へ横展開する。

ポジショニングを一文で表すなら **「分析ツール」ではなく「ルールを守り続けるための安全装置」**。

---

## 1. プロダクトの本質（抽象化）

現在の実装は株式分析ツールだが、システム構造を抽象化すると次のサイクルになる。

```
対象 (Entity)
  ↓
時系列データ (Metrics)
  ↓
判定ルール (Rules)
  ↓
イベント / シグナル (Event)
  ↓
人間の判断 (Action)   ← ここが「裁量支援」の核心
  ↓
結果 (Result)
  ↓
ルール改善 (Feedback)
  ↓
（先頭へ戻る）
```

このサイクルは特定ドメインに依存しない。株式はあくまで「最初の適用例」であり、同じ仕組みが他分野にもそのまま適用できる点が、本プロダクトの拡張余地である。

---

## 2. 開発の原体験 ＝ 独自の競合優位

このプロダクトの出発点は、開発者自身の特性のサポートにある。ここが他の「株Botサンプル」と決定的に異なる、模倣困難な提供価値の源泉である。

- **散漫さ（衝動的な判断・目移り）への対策**: ルールを緩めようとした瞬間に「内省チェックリスト」を挟み、衝動的な逸脱を抑える。
- **一貫性の喪失・無気力への対策**: 脳に負担をかけない「今日やるべき1つのアクション」に絞った超シンプルビューで、放置を防ぐ。
- **判断のブレの記録**: ルール変更の動機をテキストで残し、過去の行動をタイムライン化して振り返れる。

投資やビジネスにおける失敗の多くは「手法を知らないから」ではなく、**「感情や認知の偏りに負けて、自分で決めたルールを破ってしまうから」** 起きる。
この課題に対し、エンジニアリングスキル × 自身の特性への深い理解 がそのまま競合優位性へと昇華されている。

---

## 3. 株式投資は「適用例の一つ」

同じ監視・改善サイクルが他ドメインに展開できることを示す。

| ドメイン | 対象 | データ | ルール例 | シグナル | 行動 | 改善 |
| --- | --- | --- | --- | --- | --- | --- |
| **株式投資（現状）** | 銘柄 | 株価・出来高・指標 | W底・MACD・RSI | 売買候補 | エントリー/利確/損切り | ルール見直し |
| 生物観察 | 特定生物種 | 個体数 | 前年比20%以上減少 | 減少アラート | 現地調査 | 監視基準の変更 |
| 学習管理 | 学習者 | 学習時間 | 3日連続未達 | 停滞警告 | 学習計画見直し | 目標再設定 |
| 健康管理 | 個人 | 体重 | 7日平均で増加 | リバウンド警告 | 食事・運動見直し | 目標調整 |

「観察 → ルール適用 → 異常検知 → 通知 → 記録 → 改善」という枠組みは共通で、ドメインを差し替えるだけで成立する。

---

## 4. 市場性の考察 —— なぜ「ルール運用支援」なのか

### 株式分析ツール市場（レッドオーシャン）

- メリット: 市場規模が大きく、ユーザー数が多く、興味を持たれやすい。
- デメリット: TradingView・株探・証券会社ツールなど強力な競合が存在し、**分析機能単体での差別化は困難**。

### ルール運用支援市場（ブルーオーシャン）

本プロダクトの独自性は、分析精度ではなく次の点にある。

- ルール管理／ルール変更履歴
- 行動記録／振り返り／改善支援

ユーザーが本当に価値を感じるのは「分析できること」ではなく **「決めたルールを継続して守れること」** である可能性が高い。ここに賭ける。

---

## 5. ビジネスモデル（無料と有料の境界線）

金融商品取引法（投資助言業）などの法的リスクを回避しつつ、競合と差別化するため、機能を次のように切り分ける。

```
【無料版：集客・実例の提示】
  固定の資産運用ユースケース
    → 固定ルールによる監視・シミュレーションを体験

【有料版：マネタイズ・ユーティリティ化】
  データ・ルールの抽象化
    → ユーザー固有データ（生物・Web・在庫…）× カスタムJSONルール
    ＋ 散漫・無気力対策の行動管理エンジン
```

### 無料版（日本株スイング限定ケース）

- **目的**: 強力な集客フックとプロダクトの信頼性証明。
- **機能**: 日足ベースの株価自動取得（FastAPI + cron）、標準ルール（W底・フラッグ等）によるシグナル検知、ブラウザでのチャート・ダッシュボード閲覧、基本通知。
- **法的安全性**: 固定ルールかつ無料公開のため、投資助言業には抵触しない。

### 有料版（Pro プラン：月額サブスクリプション）

- **目的**: SaaS としての収益化と、汎用ユーティリティへの横展開。
- **機能**:
  1. **観察対象の自由化**: CSV アップロードや API 連携で、株価以外の任意の時系列データ（個体数・アクセス数・在庫・体重など）をインポート。
  2. **ルールの完全外部化（GUI エディタ）**: バックエンドの JSON ロジックを、コードを書き換えずに Web UI から編集・保存。
  3. **行動管理・ペナルティログ（特性サポートの本質）**: ルール緩和時の内省チェックリスト強制表示、変更動機の保存とタイムライン化、無気力時向けの「今日の1アクション」ビュー。
- 想定価格帯: 月額 500〜1,000 円クラスから検証。

課金してもらうのは **「分析」ではなく「継続支援」** という点が一貫した思想である。

## 6. システムアーキテクチャ（抽象化＝マルチテナント化）

技術スタックは維持したまま、データの流れを抽象化（マルチテナント化）する。

- **Backend**: Python 3.12+ / FastAPI（動的 JSON ロジック評価、ユーザー認証・認可）
- **Frontend**: HTML5 / Vue.js（動的ルールエディタ、汎用時系列ダッシュボード）
- **Database**: PostgreSQL（SQLAlchemy + Alembic、ユーザーごとのデータ隔離・履歴保存）
- **Infrastructure**: Google Cloud（GCE / GCS）＋ Render（Web UI）

現状は「Web UI = Render、計算 = GCE ワーカー」の責務分離が完了しており、有料化に向けたマルチテナント化（ユーザー単位のデータ隔離・認証）の土台は整っている。

---

## 7. 段階的ロードマップ（FastAPI 学習 × 事業化）

自身のスキルアップと事業化をシームレスに繋ぐ3ステップ。

**フェーズ1：自己利用・基礎固め**
既存の株価システムに、仮エントリー（デモトレ）の記録とルール変更履歴ログの保存・表示を実装。まず自分が毎日使う状態を作る。

**フェーズ2：無料公開・発信**
無料版として Render 等にデプロイ（完了済み）。X や技術ブログ（Qiita / Zenn）で「感情を排してルールを守るための投資シミュレーター」として発信し、初期ユーザーとフィードバックを獲得。

**フェーズ3：有料化・マルチテナント化**
FastAPI の `Depends` を用いたユーザー認証、Stripe 決済 API の組み込み、UI からの動的ルール変更（JSON の DB 管理）を実装し、完全な SaaS としてローンチ。その後、株式以外のドメインへ横展開。

## 8. 公開時の見せ方（メッセージング）

### やるべき

- README は **思想中心**に書く（「自動売買」ではなく「裁量トレード支援」「ルールを守るための装置」）。
- アーキテクチャ図と、抽象化された監視・改善サイクルを見せる。
- 開発の原体験（特性サポート）をストーリーとして語り、共感と独自性を伝える。

### やらない方がいい

- 「儲かる」系の言葉、成績アピール、売買推奨表現。
- 最初から「汎用ツールです」と抽象的に売り込むこと（価値が伝わらない）。まず株という具体で見せる。

## 9. 市場感（率直な評価）

| 観点 | 評価 |
| --- | --- |
| 技術完成度 | 高い |
| 個人運用価値 | 非常に高い |
| 株式分析としての差別化 | 低（競合過多） |
| **ルール運用支援としての独自性** | **高い** |
| 収益化の即効性 | 低（フェーズ3で本格化） |
| 横展開・スケール余地 | 高い |

## 最終結論

- このプロダクトの芯は **「ルールベース監視・改善プラットフォーム」** であり、株式分析はその最初の適用例にすぎない。
- 収益化の鍵は「分析精度」ではなく **「決めたルールを継続して守れること」への支援**。
- 戦略は **「株は入口、ルール運用支援が本命」**。具体（株）で集客し、抽象（ルール外部化＋行動管理）でマネタイズし、実績をもとに他分野へ広げる、という段階的アプローチを基本方針とする。
- 開発者自身の特性への深い理解が、そのまま模倣困難な競合優位性になっている点が、この事業計画の最大の説得力である。
